# 目标

一屏容纳 15–20 条窄行事件、关键状态一眼可见、单事件可下钻详情，同时**不丢失**现有实时流能力。子目标按优先级：

1. 可读性（P0）：窄行 + 角色语义化 + Turn 分组 + 右侧详情抽屉。
2. 诊断能力（P1）：底部聚合指标栏 + 工具内联参数→结果 + 错误红态 + 关键词搜索。
3. 全局视角（P2）：顶部三泳道时间轴 + 点击定位联动 + ASSISTANT 关联工具折叠。

# 输入（数据源与字段映射 —— 关键，勿自行假设）

## 两条数据源，先明确主从

- **会话级流**（`useSessionStream`，事件为 wire 名 `tool.call/tool.result/agent.process/message.created/done/error`，带 `turn_index`）—— LiveTailView 当前用的就是它，支持实时与回放。
- **message 级 trace**（`getTrace`，事件为内部 type `message_created/agent_process/tool_call/tool_result/tool_error/done`，带 `seq`/`created_at`/`anomaly`）—— 用于历史确认与详情下钻。

**决策**：详情抽屉与聚合优先以 `getTrace` 的 message 级事件为准（字段更完整，含 `output`/`duration_ms`）；实时增量沿用 `useSessionStream`。**`turn_index` 只有会话级流有**，message 级 trace 无 turn 概念，Turn 分组需从事件序列/`message_created` 边界推导——若两源对不齐，先向用户确认以哪个为准，不要擅自混用。

## 后端事件字段现状（已实读代码核实）

| 事件 type | 实际 payload 字段 |
|---|---|
| `message_created` | `{message_id}`（**无正文**；用户输入正文在 `Message.content` 表，需另取） |
| `agent_process` | `{state, detail?}`（state ∈ starting/planning/executing/retrying/degrading/interrupted） |
| `tool_call` | `{name, input, plan_index, request_id}` |
| `tool_result` | `{name, output, duration_ms, status:"ok"}`（**完整 output 在此，SSE 只发摘要**） |
| `tool_error` | `{name, error_code, message, retried}` |
| `done` | `{final_text, status, usage?}`（usage 为 `{prompt_tokens, completion_tokens}`） |

## 角色标签 → 数据源映射（按现状，缺的字段明确标注为"需求"）

| 目标 UI 角色 | 颜色 | 数据来源 | 现状说明 |
|---|---|---|---|
| `USER` | 蓝 | `message_created` + `Message.content` | 正文不在 trace 内，需补取 |
| `ASSISTANT` | 紫 | `done.final_text`（+ `message.delta` 流） | trace 内无独立 assistant 事件 |
| `SYSTEM` | 灰 | `agent_process`（状态事件） | 本项目不落 system prompt trace |
| `CONTEXT` | 绿 | **无对应事件** | 字段需求（见下） |
| `TOOL` | 橙 | `tool_call` → `tool_result`/`tool_error` | 字段完整 |
| `ERROR`/`ABORTED` | 红 | `tool_error` / `error` / `agent_process(state=interrupted)` | 取值见各事件 |

## 后端字段需求清单（前端先按 schema 预留，缺失时 Tab 隐藏或显示「暂无数据」，并汇总输出本文档）

| 缺口 | 影响的功能 | 建议补法 |
|---|---|---|
| 首 token 时间 `first_token_time` | 指标栏「首token平均」、时间轴 Model 泳道精确耗时 | `done`/`agent_process` 增字段 |
| 缓存命中 `cached_tokens`/`cache_read_tokens` | 指标栏「缓存命中 X%」 | `done.usage` 增字段 |
| ASSISTANT 消息结构体（content + source 来源标记） | 抽屉 `Preview`/`Source` Tab | 新增事件或扩 `done` |
| USER 输入正文 | 抽屉 `Preview` Tab | `message_created` 增 `content` 或前端从 `Message` 表取 |
| 工具 input/output schema | 抽屉 `Schema` Tab | `tool_call`/`tool_result` 携带，取自 `Tool.execution` |
| 非末轮 usage（中间轮次 LLM token） | 指标栏累计 token | loop 每轮 usage 落 trace |

# 任务（P0→P1→P2 顺序，全部完成）

## P0 —— 窄行事件流 + 详情抽屉

1. 事件条改为**单行紧凑卡片**（高 32–40px），结构 `[角色Tag] [摘要文本]`，超长省略号截断不换行；一屏 ≥ 15 条。废弃整段 JSON 展示，原始 JSON 移入抽屉 `Raw`。
2. 左侧角色 Tag 用 `el-tag`（plain/light、小圆角），颜色按上表固定映射。
3. 摘要规则：USER/ASSISTANT/SYSTEM 取前 60–80 字；TOOL 内联 `工具名 {参摘要} → {果摘要}`，失败位显红 `ABORTED`/错误信息；`agent_process` 映射为 `状态名` 灰色次要展示。
4. 按 Turn 分组，组首显 `Turn N`（浅灰底小字），`el-collapse` 折叠，默认展开、最新组滚动到可视区；Turn 内有 Step 再子分组。
5. 右侧抽屉（`el-drawer` rtl，宽 380–420px）：标题 `[角色Tag] Turn N · Message` / `· Step N`；点击切换内容不关闭；选中事件条蓝左边框高亮。
   - 普通消息 Tab：`Summary`(角色/所属Turn/状态/耗时) · `Preview`(正文预览) · `Raw`(JSON+复制) · `Source`(来源，缺字段时隐藏)
   - 工具 Tab：`Summary` · `Payload`(参数 JSON+复制) · `Result`(结果 JSON+复制) · `Schema` · `Timing`(started/duration/source)
   - 每个 JSON 区右上角「复制」(`el-button` text+图标)；无数据 Tab 隐藏。

## P1 —— 指标栏 + 诊断能力

6. 底部替换 `session_id/事件7/token0/已连接` 为密集指标行：`N轮 · M步 | LLM总耗时 Xs · 工具总耗时 Ys | 首token平均 Zs · 吞吐 N tok/s | 缓存命中 X% | 输入 XK tok · 输出 YK tok | 错误 N`——全部前端从事件流聚合（缺字段项显示 `—`）。
7. 工具调用内联参数→结果（复用 P0 摘要）；错误事件红色可辨；右侧搜索框（`el-input` 带搜索图标）按关键词过滤。

## P2 —— 时间轴 + 联动

8. 事件流上方横向时间轴（ECharts custom series 或甘特，不引新依赖），三条泳道 `Input`(灰)/`Model`(紫)/`Tools`(橙，失败段标红)，色块横向长度映射耗时、无耗时事件最小固定宽。
9. 点击色块 → 左侧定位到对应事件并高亮 + 打开抽屉；选中事件蓝色边框在两个视图联动。时间轴上方三视图切换 `Duration`/`Turns`/`Calls`。
10. ASSISTANT 消息后紧跟工具调用时，其下显示灰色 `... N tool calls`，点击展开/折叠关联 TOOL 事件。

## 设计说明

1. **补了「第一步先读文件」**——这是原提示词最大隐患：没告诉 AI 改造对象文件名（`LiveTailView.vue` 而非 TracePanel）、参考仓库精确路径、后端字段真相都藏在哪。让 AI 读事实而非空想，直接消掉「后端字段韧判→返工」和「参考界面全靠想象」两个风险。
2. **把「后端字段需求清单」从愿望变成可执行**：实读后端后把 6 个事件的真实 payload、6 个缺失字段及建议补法摆成表，AI 无需再猜。
3. **显式化了「角色↔数据源」映射**：原提示词假设 SYSTEM/CONTEXT/ASSISTANT 都有对应事件，但实读发现本项目 trace 里**没有** CONTEXT、没有独立 assistant 事件、`message_created` 没有正文。不点破这层，AI 会把紫色 ASSISTANT 标签挂到不存在的事件上。
4. **补了一条数据源取舍**（使用 `getTrace` vs `useSessionStream`）：`turn_index` 只在会话级流有，是「Turn 分组」最容易踩的坑，已列为需确认点。
5. **默认假设**：验收标准里新增 `npm run build` 类型检查通过、以及「< 500 条事件暂不做虚拟滚动」——这两项原提示词有提到虚拟滚动但没给验收口径，补为显式阈值（可按需改）。
